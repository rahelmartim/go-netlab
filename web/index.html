UDP: fire and forget

UDP sends each datagram once. There is no connection, no acknowledgment, and no retransmission. Datagrams can arrive late, out of order, or never. It is fast and simple, so apps like games, voice, and video calls use it.

TCP: reliable and in order

TCP opens a connection with a 3-way handshake (SYN, SYN-ACK, ACK). The receiver acknowledges the data, and the sender retransmits what is lost. The app always gets the bytes in order, but a lost segment makes the later data wait.

          A caption and a 48 × 48 image travel as one payload. Over UDP, lost packets leave holes in the picture. Over TCP, the picture is always complete, but it fills from top to bottom and waits for every lost piece.

          Distribution

          Delay The time that a packet needs to cross the network, one way.
          Jitter The change of the delay from packet to packet. NetLab measures it as in RFC 3550.
          Loss The share of packets that never arrive.
          Bandwidth How many bits per second the link sends. Large packets wait in a queue.

          TCP flavors: congestion control

          The congestion window (cwnd) is how much data TCP sends before it waits for ACKs. Each flavor grows and cuts it in its own way. Send the same file with each one, over a link with a bottleneck.

          README.TXT

          NetLab simulates a network in Go and runs in your browser with WebAssembly. Each run is deterministic: the same seed and conditions give the same packets.

          The TCP model is simplified, but it has the main parts of real TCP: the 3-way handshake, a sliding window, cumulative ACKs, an adaptive retransmission timeout (RFC 6298), fast retransmit after 3 duplicate ACKs, and connection close.
